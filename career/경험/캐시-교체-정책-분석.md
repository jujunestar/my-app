# 컴퓨터 구조 Architectural Simulation — 캐시 교체 정책 분석

## 문제
컴퓨터 구조 수업의 Architectural Simulation 프로젝트에서 팀(7팀, 조장) 역할을 분담했다.
내 담당은 프로젝트 4번 3, 캐시 교체 정책(LRU/FIFO/RANDOM)에 따른 성능 분석 시뮬레이션과 보고서였다.
교체 정책은 단일 지표로 평가하기 어려워 AMAT와 CPI 두 지표로 비교해야 했다.

## 과정
dl1·dl2 miss rate와 CPI를 성능 지표로 선택하고, AMAT(L1 Hit 1 cycle, L2 Hit 10 cycle, 메모리 100 cycle 가정)를 계산해 비교했다.
block size 32B, associativity 4-way, dl1-128, dl2-1024로 고정하고, L1·L2 정책 3종을 조합한 9가지 경우를 GCC·ANAGRAM·COMPRESS95·GO에서 시뮬레이션했다.
시뮬레이션 오류(설치 문제, block size 통일 문제)는 익명 게시판 질문과 팀원 간 교차 검증으로 해결했다.

## 해결
워크로드마다 최적 정책이 달랐다 — GCC는 L-L(LRU-LRU)이 최소 AMAT(1.710)·최소 CPI(0.8563), ANAGRAM은 L-R(LRU-RANDOM)이 최소 CPI(0.4692)였다.
COMPRESS95는 L-L, F-F, F-L, R-L, R-F, L-F 조합이 같은 최소 AMAT(16.17)를 기록했다.
2차로 프로젝트 5번(gcc, anagram) 최적 캐시 구성 탐색 시뮬레이션과 보고서를 담당했다.

## 결과
GCC는 block size 128B, L1 8-way, L2 4-way, L-L 정책 조합에서 CPI 0.7511로 최저였다.
ANAGRAM은 같은 캐시 설정에서 R-F·R-L 정책일 때 CPI 0.4471로 최저였다.
특정 워크로드에 최적화된 정책이 모든 상황에서 좋은 성능을 보장하지 않음을 결론으로 정리했다.
